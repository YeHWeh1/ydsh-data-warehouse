> 对应任务书子任务 4、5，部署操作手册步骤 1~6

## 一、部署架构

| 服务 | 镜像 | 宿主机端口 | 作用 | 健康检查方式 |
|---|---|---|---|---|
| `meta-mysql` | mysql:8.0 | 3307 | Hive Metastore 元数据库 | `mysqladmin ping` |
| `hive-metastore` | apache/hive:4.0.0 | 9083 | 元数据服务 | 依赖 mysql 健康 |
| `hive-server` | apache/hive:4.0.0 | 10000 | HiveServer2（重计算） | TCP 探测 10000 端口 |
| `clickhouse` | clickhouse/clickhouse-server:24.8 | 8123 / 9000 | 加速层（大屏秒级查询） | `clickhouse-client select 1` |
| `superset` | apache/superset:4.1.2 | 8088 | BI 仪表板 | `curl /health` |
| `dsh-app` | 本地构建 | 8000 / 8501 | 数据接口 + 大屏 + Streamlit | `curl /api/live` |

> **编排复用**：`第4周/docker-compose.yml` 用 `include: ../第1周/docker-compose.yml` 引入前三个服务，
> 不复制配置，避免两周配置漂移。项目名固定 `dshproject`，数据卷 `dshproject_*` 与前几周共用。

**启动依赖链**（全部用 `condition: service_healthy`，不是裸 `depends_on`）：

```
mysql(healthy) → hive-metastore → hive-server(healthy) ─┐
                                                        ├→ superset
clickhouse(healthy) ────────────────────────────────────┤
                                                        └→ app
```

## 二、首次部署步骤

### 2.1 前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Docker Desktop | 已启动，WSL2 后端 | `docker info` |
| 磁盘 | 至少 15 GB 可用 | `docker system df` |
| 端口 | 3307/9083/10000/8123/9000/8088/8000/8501 未被占用 | `netstat -ano \| findstr :8088` |
| 前三周数据 | 已跑过第 1/2/3 周（ADS 表存在） | 见 2.5 |

### 2.2 生成 `.env`（密钥配置）

```powershell
cd 第4周
copy .env.example .env
```

编辑 `.env`，**必须填写**以下三项（其余可留默认）：

| 变量 | 是否必填 | 说明 |
|---|---|---|
| `CLICKHOUSE_PASSWORD` | ✅ 必填 | ClickHouse 应用账号口令。留空 compose 直接拒绝启动 |
| `SUPERSET_SECRET_KEY` | ✅ 必填 | Superset 会话加密密钥，建议 ≥48 字符 |
| `SUPERSET_ADMIN_PASSWORD` | ✅ 必填 | Superset 管理员口令 |
| `DEEPSEEK_API_KEY` | 选填 | 留空则 NL2SQL 走规则引擎兜底，现场断网也能演示 |
| `CLICKHOUSE_USER` | 选填 | 默认 `ydsh`（不用 `default`，遵循权限最小化） |

**不想手填**：直接运行生成脚本，自动产出随机强口令：

```powershell
python 第4周\scripts\gen_env.py
```

> 脚本只回显口令**长度**，不打印明文；`.env` 已在 `.gitignore` 中，不会被提交。

### 2.3 一键部署

```powershell
# 双击
第4周\一键部署.bat

# 或命令行
powershell -ExecutionPolicy Bypass -File 第4周\scripts\deploy.ps1
```

脚本依次执行 6 步：检查 Docker → 校验 `.env` → `compose up -d --build` → 等 Hive 就绪 → 建 ADS 表 → 同步 ClickHouse → 冒烟测试 → 打印地址。

常用参数：

| 参数 | 用途 |
|---|---|
| `-SkipBuild` | 只改了代码、不重建镜像 |
| `-SkipSync` | 数据没变、跳过 ClickHouse 同步 |
| `-SkipTest` | 跳过冒烟测试，快速起服务 |

### 2.4 验证部署

```powershell
# 全栈冒烟测试（30 项）
python 第4周\scripts\smoke_test.py

# Superset 数据源真实查询
$env:SUPERSET_ADMIN_PASSWORD="你的口令"
python 第4周\scripts\verify_superset.py

# 大屏渲染验证（需 Chrome）
chrome --headless=new --remote-debugging-port=9222 about:blank
node 第4周\scripts\verify_screen.js
```

**预期结果**：冒烟测试 `30/30 通过`；Superset 两个数据源均能查出数据；大屏 8 个图表 `✓`。

### 2.5 前置数据准备（若前三周未跑过）

第 4 周依赖前三周产出的 `ydsh_ads` 表。**从零开始**时按顺序执行：

```powershell
# 1) 起环境 + 建 ODS 表 + 导入 CSV
cd 第1周
docker compose up -d
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000" --silent=true < sql\ods\create_ods.sql
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000" --silent=true < sql\ods\load_ods.sql
# 预期：1000 / 600 / 60 / 15600 / 37549 / 60000，合计 114,809 行

# 2) 第 1 周清洗（DWD 层）
powershell -File scripts\run-all.ps1

# 3) 第 2 周（四层数仓 + EDA）
powershell -File ..\第2周\scripts\run-week2.ps1 -NoPause

# 4) 第 3 周（DWS/ADS 扩展 + NL2SQL）
powershell -File ..\第3周\scripts\run-week3.ps1 -NoPause

# 5) 回到第 4 周
cd ..\第4周
powershell -File scripts\deploy.ps1
```

> ⚠️ **已知坑**：`第1周\一键运行.bat` 只做「清洗」，**不含 ODS 建表与导入**。从零重建时必须先手工跑上面第 1 步的两条 SQL，否则清洗会因 `Table not found 'ods_user'` 全部失败，而脚本仍会打印「全部完成」。

## 三、Superset 仪表板配置（子任务 1）

> 数据源已由 `superset/bootstrap.sh` 自动注册，**无需手工添加**。
> 但「5 个图表 + 联动筛选」属于 UI 操作，需手工完成（Superset 的图表 JSON 在版本间不兼容，脚本化不可靠）。

### 3.1 登录

浏览器打开 http://127.0.0.1:8088/，用 `.env` 里的 `SUPERSET_ADMIN_USER` / `SUPERSET_ADMIN_PASSWORD` 登录。

### 3.2 确认数据源（已自动完成）

`Settings → Database Connections`，应看到两个：

| 名称 | 连接串 |
|---|---|
| Hive 数仓（ydsh_ads） | `hive://hive@hive-server:10000/ydsh_ads` |
| ClickHouse 加速层（ydsh_ads） | `clickhousedb://ydsh:****@clickhouse:8123/ydsh_ads` |

点 `Test Connection` 应显示 "Connection looks good"。

### 3.3 创建数据集（Datasets）

`Datasets → + Dataset`，数据源选 **ClickHouse 加速层**，schema 选 `ydsh_ads`，依次添加：

| 表名 | 用途 | 对应图表 |
|---|---|---|
| `screen_kpi` | KPI 卡片 | 大数字 |
| `sales_daily` | 日趋势 | 折线图 |
| `category_topn` | 品类排行 | 柱状图 |
| `region_rank` | 省份分布 | 地图 |
| `paytype_share` | 支付占比 | 饼图 |
| `store_rank` | 门店排行 | TopN 表 |
| `hour_category_heat` | 时段热力 | 热力图 |

> 选 ClickHouse 而不是 Hive：Superset 每次渲染图表都发查询，Hive 单次要 2.6 秒，仪表板 5 个图表就要 13 秒；ClickHouse 合计不到 1 秒。

### 3.4 制作 5 个图表

任务书要求「至少 5 个图表」，对应关系：

| # | 图表 | 数据集 | 图表类型 | 配置要点 |
|---|---|---|---|---|
| 1 | 销售趋势折线图 | `sales_daily` | Line | X=`order_date`，Y=`gmv`，加 `ma7` 双系列 |
| 2 | 品类销售柱状图 | `category_topn` | Bar | X=`category`，Y=`gmv`，按 `rank_no` 排序 |
| 3 | 区域分布地图 | `region_rank` | Map | 地区=`province`（需去掉「省/市」后缀），指标=`gmv` |
| 4 | 支付方式占比饼图 | `paytype_share` | Pie | 维度=`pay_type`，指标=`gmv` |
| 5 | TopN 排行表 | `store_rank` | Table | 列：`rank_no`/`store_name`/`gmv`/`aov`/`gmv_per_sqm`，按 `gmv` 降序，行数限制 10 |

### 3.5 组合仪表板与联动

1. `Dashboards → + Dashboard`，命名「云购生活 · 经营分析」。
2. 把 5 个图表拖入，按「顶部 KPI → 左趋势 → 右结构 → 底部排行」布局。
3. 添加筛选器：`+ Add filter` → 选 `sales_daily.order_date`（时间范围）、`category_topn.category`（多选）。
4. **联动**：编辑仪表板 → 点图表右上角 `⋮` → `Edit chart` → 在 `Advanced` 里设 `Emit cross filters` / 在目标图表设 `Receive cross filters`。点柱状图的某个品类，折线图会跟着过滤到该品类。
5. 保存后点 `View as Guest` 或退出重登，确认非管理员也能看到（`PUBLIC_ROLE_LIKE = Gamma`）。

## 六、API 配置指南（密钥安全，子任务 5）

### 6.1 密钥清单与来源

| 密钥 | 用途 | 存放位置 | 泄露影响 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | NL2SQL 调用大模型 | `.env` → 容器环境变量 | 被盗刷额度 |
| `CLICKHOUSE_PASSWORD` | 应用连 ClickHouse | `.env` → 容器环境变量 | 数据库被读写 |
| `SUPERSET_SECRET_KEY` | Superset 会话签名 | `.env` → 容器环境变量 | 会话伪造 |
| `SUPERSET_ADMIN_PASSWORD` | Superset 管理员 | `.env` → 容器环境变量 | 仪表板被篡改 |

### 6.2 六条安全措施

| # | 措施 | 落地 |
|---|---|---|
| 1 | **不硬编码** | `docker-compose.yml` 只有 `${VAR}`，全仓库无明文口令 |
| 2 | **缺失即拒启动** | compose 用 `${VAR:?提示}`，没配就报错，不会用空口令跑起来 |
| 3 | **不落盘** | 密钥只在 `.env`（`.gitignore`）与容器环境变量，不写进镜像层 |
| 4 | **随机生成** | `gen_env.py` 用 `secrets.token_urlsafe(48)` |
| 5 | **不回显** | 脚本只打印长度；`llm_client.sanitize()` 对 `sk-xxx` 打码 |
| 6 | **权限最小化** | app 容器非 root（uid 1000）；ClickHouse 用专用账号 `ydsh` 而非 `default`；Superset 不开匿名访问 |

### 6.3 密钥轮换流程

```powershell
# 1) 生成新口令，只改 .env 对应行
python -c "import secrets;print(secrets.token_urlsafe(24))"

# 2) 重建受影响的服务（不必全栈重启）
docker compose -f 第4周/docker-compose.yml up -d --force-recreate clickhouse app

# 3) 验证
python 第4周\scripts\smoke_test.py
```

> 换 `SUPERSET_SECRET_KEY` 后所有用户需重新登录（旧会话失效），这是预期行为。

## 七、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `compose up` 报 `CLICKHOUSE_PASSWORD 未设置` | `.env` 缺项 | 补齐 `.env` 或跑 `gen_env.py` |
| `hive-server` 反复 Restarting，日志有 `HiveServer2 running as process 7` | 容器 `/tmp` 残留 pid 文件 | `docker compose ... up -d --force-recreate hive-server` |
| Superset 报 `NOT NULL constraint failed: ab_role.name` | `AUTH_ROLE_PUBLIC` 设成了 `None` | 改成字符串 `"Public"`（已修正） |
| Superset 报 `Results backend is not configured` | 缺 `RESULTS_BACKEND` | 已在 `superset_config.py` 配 `FileSystemCache` |
| Superset 报 `sasl` 装不上 / `g++ not found` | 用了 `pyhive[hive]`，会编译 C 扩展 | 装基础版 `pyhive`（NOSASL 不需要 sasl） |
| Superset API 401 / CSRF missing | Bearer 方式与 CSRF 冲突 | 用 session 登录 + `/api/v1/security/csrf_token/`（见 `verify_superset.py`） |
| 大屏图表空白但接口有数据 | 浏览器缓存了旧 JS | `Ctrl+Shift+R` 强刷 |
| 大屏饼图/散点被压得很扁 | 右列塞了 3 个面板 | 已调整为 2 个，堆叠图移到下行 |
| `docker pull` 卡住或超时 | Docker Desktop 配了不存在的代理 | 设置 → Resources → Proxies 改为 system；或配 `registry-mirrors` |
| ClickHouse 表空 | 没跑同步 | `docker exec dsh-app python /app/sync_clickhouse.py` |
| PowerShell 脚本报「字符串缺少终止符」 | 文件无 UTF-8 BOM，PS 5.1 按 GBK 读 | 保存为「UTF-8 with BOM」 |
